# Security reporting

Use the repository's private vulnerability-reporting feature for sensitive issues. If it is unavailable, open an issue asking for a private reporting channel without exploit details or private data.

Include the exact source revision, affected input or route, expected/actual behavior and a minimal synthetic reproduction. Never include secrets, actual cloud reports, account inventory or session cookies. Test only your own local instance.

This app is intended for loopback-only personal use. Its README documents the limits of ephemeral state, browser isolation, report-derived scores and exports. Defects in the implemented upload, CSRF, escaping, storage or isolation controls remain reportable.
